
## 测试策略

### 单元测试

```bash
npm test
```

使用 Node 内置 `node:test`，不引入额外测试框架。当前 30 项测试。

覆盖：

- `LibraryStore`：写入、更新、全量替换、删除清理；
- `ExtensionStore`：安装、列表、启用/禁用、移除、无效 manifest；
- `ExtensionHost`：搜索、结果归一化、resolve 输出文件、子进程退出清理；
- `ExtensionScheduler`：任务注册、持久化、成功/失败状态；
- `LikesStore`：忽略列表去重、配置边界；
- `buildSourceRegistry`：内置源、扩展来源自动注册、禁用过滤；
- `files`：标题前缀清洗、安全文件名；
- `provenance`：下载来源写入、重载、未知来源边界；
- `recent`：条数、天数、字节上限和去重清理。

### 集成/冒烟

- 打包后启动 Portable，检查窗口、音乐库、搜索、扩展下载、主题和界面比例；
- 任何“只在真实 UI 出现”的问题，必须用真实进程复现，不以单元测试通过代替。

### 规则

- 先写或更新测试，再改实现；
- 失败测试优先于临时手动验证；
- 测试不能依赖个人目录、外部网络或真实平台账号。

## 测试矩阵

| 修改类型 | 必须补的测试 |
|---|---|
| 播放/队列/历史 | 纯函数单测 + 实际播放冒烟 |
| 搜索/来源注册 | 纯函数单测 + 来源列表冒烟 |
| 下载/删除/入库 | 服务单测 + 真实文件路径测试 |
| 扩展安装/解析 | 宿主子进程测试 + manifest 校验 |
| 定时/同步 | 调度器状态机测试 + 失败重试 |
| 主题/比例 | 配置/纯函数测试 + 真实重启或截图验收 |

新增或修改重要功能时，如果 PR/变更没有对应测试，视为未完成。
